**Why a separate account?**
Using the owner's personal password in firmware is a security risk — if the device or codebase is compromised, the attacker gains full account access. The device account is isolated: if leaked, it can only write sensor data. It cannot issue valve commands or access any other data.

**How it was created (REST API — Firebase CLI has no `create user` command):**

```bash
# 1. Generate a strong random password
openssl rand -base64 16

# 2. Create the user via Identity Toolkit REST API
curl -s -X POST \
  "https://identitytoolkit.googleapis.com/v1/accounts:signUp?key=AIzaSyDEAP1XKmK8t1qt4fuXYN2ndZ3pbNNlLTU" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "esp32-irrigation@device.local",
    "password": "<generated-password>",
    "returnSecureToken": true
  }' | python3 -m json.tool
```

The response `localId` field is the UID — save it for use in security rules.

**To verify credentials work:**


## 3. Realtime Database (RTDB)

### Existing data
`/iot2025/` — pre-existing smart home data. Do not modify.

### Irrigation data
`/irrigation/` — created automatically by the ESP32 firmware on first boot. No manual setup needed.

All data is scoped under a **site key** (`irrigation/sites/{siteId}/`). The PWA creates the site key when you first open the app (default key: `default`). The firmware reads `SITE_ID` from `config.h` — this must match.

**Schema:**
```
/irrigation/
  sites/
    {site_id}/           # e.g. "default" or "-OAbc123" (generated by PWA push)
      meta/
        name: string
        createdAt: number
      zones/
        {zone_id}/       # "balcony" | "garden" — must match ZONE_1_ID / ZONE_2_ID in config.h
          meta/
            name: string
            enabled: boolean
            px: number   # map pin position (0–100%)
            py: number
          sensor/
            moisturePercent: number
            rawValue: number
            timestamp: number    # ServerValue.TIMESTAMP
          valve/
            state: "OPEN" | "CLOSED"
            lastChangedAt: number
            openedBy: "auto" | "manual" | "schedule"
          command/
            action: "OPEN" | "CLOSE" | null   # written by PWA, cleared by firmware
            issuedAt: number
            issuedBy: string
          schedule/
            {schedule_id}/
              hour: number
              minute: number
              durationMinutes: number
              enabled: boolean
              days: [0,1,2,3,4,5,6]   # 0=Sun, 6=Sat
          history/
            {push_id}/
              moisturePercent: number
              rawValue: number
              timestamp: number
              valveOpen: boolean
      devices/
        {device_id}/     # "esp32-01" — must match DEVICE_ID in config.h
          firmware: string
          lastSeen: number
          ipAddress: string
          wifiRssi: number
      settings/
        alerts/
          telegram: { token, chatId }
          offlineMinutes: number
          offlineEnabled: boolean
          zones: { {zone_id}: { threshold, enabled } }
      auditLog/
        {push_id}/
          action: string
          zone: string
          details: object
          timestamp: number
          user: string
```

**To inspect RTDB data via CLI:**

```bash
# Check all sites
firebase database:get /irrigation/sites \
  --project smarthomeapp-982da \
  --instance smarthomeapp-982da-default-rtdb

# Watch live sensor data (replace "default" with your site key)
firebase database:get /irrigation/sites/default/zones/balcony/sensor \
  --project smarthomeapp-982da \
  --instance smarthomeapp-982da-default-rtdb \
  --watch

# Check device heartbeat
firebase database:get /irrigation/sites/default/devices/esp32-01 \
  --project smarthomeapp-982da \
  --instance smarthomeapp-982da-default-rtdb
```

## 4. Security Rules

Rules are stored in `database.rules.json` at the repo root and deployed via `firebase.json`.

### Access matrix

| Path | Owner | ESP32 device | Anyone else |
|---|---|---|---|
| `/iot2025/` | read + write | none | denied |
| `irrigation/sites/{id}/zones/{id}/sensor/` | read | write | denied |
| `irrigation/sites/{id}/zones/{id}/valve/` | read | write | denied |
| `irrigation/sites/{id}/zones/{id}/command/` | write | read + write (clear only) | denied |
| `irrigation/sites/{id}/zones/{id}/schedule/` | read + write | read | denied |
| `irrigation/sites/{id}/zones/{id}/history/` | read | write | denied |
| `irrigation/sites/{id}/devices/` | read | write | denied |
| `irrigation/sites/{id}/settings/` | read + write | none | denied |
| `irrigation/sites/{id}/auditLog/` | read + write | none | denied |
| everything else | denied | denied | denied |

### Deploy rules

```bash
# From the repo root (firebase.json must exist)
firebase deploy --only database --project smarthomeapp-982da
```

### Redeploy from scratch

If rules are ever lost or corrupted:

```bash
# Verify syntax before deploying
firebase database:rules --project smarthomeapp-982da \
  --instance smarthomeapp-982da-default-rtdb

# Deploy
firebase deploy --only database --project smarthomeapp-982da
```

## 5. Recreating Everything from Scratch

If you need to set up a fresh Firebase project:

1. Create project at console.firebase.google.com
2. Enable **Authentication > Email/Password** sign-in method
3. Create RTDB in the region closest to your device
4. Run `firebase login` and `firebase projects:list` to confirm access
5. Create the owner account in Firebase Console > Authentication > Users
6. Create the device account using the `curl` command in section 1
7. Note both UIDs and update `database.rules.json`
8. Update all values in `config.h` (API key, DB URL, device email/password, SITE_ID)
9. Open the PWA, go to Settings → note the site key shown (or check Firebase under `irrigation/sites/`) — set `SITE_ID` in `config.h` to match
10. Deploy rules: `firebase deploy --only database --project <project-id>`
11. Flash the firmware — the `irrigation/sites/{SITE_ID}/` path will be created on first boot
